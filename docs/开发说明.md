# 开发说明

给想在 Fingertype 基础上改、或者从头做自己版本的人（和你的 AI agent）看的技术说明。

## 1. 整体结构

```
┌────────────┐  UART 57600   ┌──────────────────────┐  蓝牙键盘 / USB 键盘   ┌───────┐
│ HLK-ZW111  │ ◀──────────▶ │  XIAO ESP32S3 固件     │ ────────────────────▶ │  Mac  │
│ 指纹模块    │  EF01 协议    │  （本仓库 src/）        │ ◀── 配置通道（JSON） ── │ 设置网页│
└────────────┘               └──────────────────────┘   蓝牙 GATT 或 USB 串口  └───────┘
```

- **指纹模块**自己完成指纹的录入、存储和比对，只把“匹配到第几号指纹”告诉主控。指纹数据不会离开模块。
- **固件**记录每个指纹编号绑定什么操作（输入哪个密码 / 按哪个快捷键 / 不执行），密码加密存在 ESP32 的闪存（NVS）里。
- 识别成功后，固件像键盘一样把密码打出来：插着数据线连电脑时用 USB 键盘，否则用蓝牙键盘。
- **设置网页**是一个本地 HTML 文件，通过蓝牙（Web Bluetooth）或 USB 串口（Web Serial）和设备通信。它也嵌在固件里，设备插线时会显示成一个只读 U 盘，里面就是这个网页。

## 2. 硬件

| 零件 | 说明 |
|---|---|
| Seeed Studio XIAO ESP32S3 | 主控。8 MB 闪存，支持 USB OTG（同时当键盘、串口、U 盘）和蓝牙 BLE |
| 海凌科 HLK-ZW111（ZW101 也行） | 电容式指纹模块，带光圈 LED，串口通信，容量 100 枚 |

接线：

| 指纹模块 | XIAO | 固件里的名字（`src/config.h`） |
|---|---|---|
| VCC（3.3V） | 3V3 | — |
| 触摸电源（3.3V） | D3 / GPIO4 | `PIN_FP_TOUCH_POWER` |
| GND | GND | — |
| TX | D7 / GPIO44 | `PIN_FP_RX` |
| RX | D4 / GPIO5（**不要接 D6**） | `PIN_FP_TX` |
| 触摸输出 | D1 / GPIO2 | `PIN_FP_TOUCH` |

板载的 BOOT 键（GPIO0）用作“运行中长按 10 秒恢复出厂”，橙色 LED（GPIO21）在按住 BOOT 键时闪烁。

## 3. 开发环境

- [PlatformIO](https://platformio.org/)，平台 `espressif32`，框架 Arduino（ESP32 Arduino core 3.x），板子 `seeed_xiao_esp32s3`。
- 依赖库（`platformio.ini` 里的 `lib_deps`）：ArduinoJson 7、NimBLE-Arduino 2.x。
- 关键编译选项：`-DARDUINO_USB_MODE=0 -DARDUINO_USB_CDC_ON_BOOT=0`。这块板子要同时当 USB 键盘、USB 串口和 U 盘，所以关掉 Arduino 默认的 USB 设置，在 `setup()` 里自己按顺序初始化，并声明“支持远程唤醒”，Mac 睡眠时按键才能唤醒电脑。
- `scripts/embed_web.py` 是编译前脚本：把 `web/Settings.html` 转成 `src/web_page_data.h`，嵌进固件。所以**改了网页要重新编译固件**，配置盘里的网页才会更新。

常用命令：

```bash
pio run                       # 编译
pio run -t upload             # 用数据线刷入
python3 scripts/devcmd.py '{"cmd":"info"}'   # 通过 USB 串口给设备发一条命令（需要 pyserial）
```

## 4. 代码结构

| 文件 | 作用 |
|---|---|
| `src/config.h` | 所有引脚和参数（见第 9 节） |
| `src/main.cpp` | 主流程：检测手指 → 识别 → 执行操作；处理网页发来的所有命令 |
| `src/fp_module.*` | 指纹模块驱动（海凌科 EF01 串口协议） |
| `src/store.*` | 闪存里的数据：密码（AES-256-GCM 加密）、指纹绑定、设置、失败次数 |
| `src/ble_keyboard.*` | 蓝牙键盘、配对限制、蓝牙配置通道 |
| `src/config_drive.*` | 只读配置盘（FAT12，每个扇区按需现算，不额外占闪存） |
| `src/ota.*` | 在线升级固件 |
| `web/Settings.html` | 设置网页（单个 HTML 文件，没有外部依赖） |
| `scripts/embed_web.py` | 编译前把网页嵌进固件 |
| `scripts/devcmd.py`、`scripts/flash.sh` | 开发调试用 |

## 5. 平时的工作流程

1. 主循环每 40 毫秒问一次模块“有没有手指”（`FP_POLL_MS`）。
2. 有手指 → 采图 → 生成特征 → 在模块的指纹库里搜索。
3. 匹配成功 → 查这个指纹编号绑定的操作：
   - **输入密码**：先轻按一下 Shift 唤醒屏幕，等待 `wakeDelay`（默认 800 毫秒），再输入密码，可选按回车；
   - **快捷键**：按下并松开一个组合键；
   - **不执行**：只闪蓝灯。
4. 输出方式：插着数据线连电脑 → USB 键盘；否则蓝牙；蓝牙暂时断开时最多等 6 秒重连。
5. 插着数据线时，如果按的是“设置入口指纹”，要等抬手才执行；按住 5 秒则改为弹出配置盘，不执行。
6. 不匹配 → 失败次数 +1，连续 5 次锁定 30 秒，之后每多 5 次锁定时间翻倍，最长 10 分钟。

## 6. 配置通道协议

网页和设备之间是**一行一个 JSON**（以 `\n` 结尾），蓝牙和 USB 串口的内容完全相同。

- **USB**：USB 串口（CDC），网页用 Web Serial 打开（波特率随意，固定 DTR=1、RTS=0）。
- **蓝牙**：自定义 GATT 服务，要求加密，且只接受已配对的电脑。

| 名称 | UUID | 方向 |
|---|---|---|
| 配置服务 | `f1e70001-74a0-4461-b8ef-90a81cb4120e` | — |
| RX（写，支持有应答和无应答） | `f1e70002-74a0-4461-b8ef-90a81cb4120e` | 网页 → 设备 |
| TX（通知） | `f1e70003-74a0-4461-b8ef-90a81cb4120e` | 设备 → 网页 |

一条命令写不下时可以分多次写入，设备按 `\n` 拼成一行。蓝牙一行最长 4 KB，USB 一行最长 8 KB。

### 请求和回复

请求：`{"id": 1, "cmd": "命令名", ...参数}`
回复：`{"re": 1, "ok": true, ...结果}`，失败时 `{"re": 1, "ok": false, "error": "错误代码"}`

设备里已经有指纹时，标了 🔒 的命令需要先验证：先发 `auth`（用户在设备上按一次已录入的手指），之后 2 分钟内可以修改。没验证会返回 `auth_required`。

| 命令 | 参数 | 说明 |
|---|---|---|
| `info` | — | 设备状态：固件版本、模块状态、密码列表（只有名称）、指纹列表和绑定、蓝牙状态、各项设置 |
| `auth` | — | 请用户按手指验证 |
| `logout` | — | 结束验证 |
| `setAccount` 🔒 | `i`（0–3）、`name`、`password`（留空 = 不改）、`enter` | 新增或修改密码 |
| `delAccount` 🔒 | `i` | 删除密码 |
| `enroll` 🔒 | `name`、`action` | 录入新指纹（按 4 次） |
| `setFinger` 🔒 | `fingerId`、`name`、`action` | 修改指纹的名称和绑定的操作 |
| `delFinger` 🔒 | `fingerId` | 删除指纹 |
| `setSummon` 🔒 | `fingerId`（-1 = 取消） | 设置“设置入口指纹” |
| `settings` 🔒 | `wakeDelay`（0–5000 毫秒） | 唤醒等待时间 |
| `identify` | — | 只识别、不执行，用来测试 |
| `typeTest` 🔒 | `via`（`ble` / `usb`）、`text`（可选） | 测试输出通道，打一段测试文字 |
| `testShortcut` 🔒 | `mod`、`key` | 测试一个快捷键 |
| `pairing` 🔒 | — | 打开 60 秒的配对窗口，允许新电脑配对 |
| `clearBonds` 🔒 | — | 删除所有已配对的电脑 |
| `reset` 🔒 | — | 恢复出厂 |
| `cancel` | — | 取消正在等手指的操作 |
| `otaBegin` 🔒 / `otaData` / `otaEnd` / `otaAbort` | 见第 8 节 | 升级固件 |

`action`（指纹绑定的操作）的三种写法：

```json
{"type": "password", "account": 0}
{"type": "shortcut", "mod": 9, "key": 20}
{"type": "none"}
```

快捷键的 `mod` 是修饰键位：⌃ = 1、⇧ = 2、⌥ = 4、⌘ = 8，可以相加（9 = ⌃⌘）；`key` 是 USB HID 键码（20 = Q，所以上面这个是 ⌃⌘Q 锁屏）。

### 设备主动发来的事件

格式：`{"evt": "事件名", ...}`

| 事件 | 什么时候 |
|---|---|
| `prompt` | 需要用户按手指（验证或识别） |
| `enroll` | 录入进度：`step` / `of`，`action` 是 `press`（请按）或 `lift`（请抬手） |
| `retry` | 录入时这次没按好，`msg` 是原因 |
| `match` | 平时识别成功：`id`、`name`、`typed`（是否执行了）、`via`（`ble` / `usb`） |
| `nomatch` | 平时识别失败 |
| `bad_image` | 图像不清楚（不计失败） |
| `locked` | 锁定中：`seconds` |
| `no_fingers` | 还没录入任何指纹 |
| `summon` | 设置入口指纹长按，`drive` 表示配置盘是否已出现 |
| `factory_reset` | 用 BOOT 键恢复了出厂 |

## 7. 数据存储

全部存在 ESP32 的 NVS（闪存里的键值存储区），命名空间 `ftype`：

| 键 | 内容 |
|---|---|
| `dk` | 32 字节随机密钥，用来加密密码（默认存在闪存里，见 README 的安全说明） |
| `a{i}p` | 第 i 个密码：随机数（12 字节）+ 校验标签（16 字节）+ AES-256-GCM 密文；附加数据绑定了位置 i，密文挪到别的位置会解密失败 |
| `a{i}n`、`a{i}e` | 第 i 个密码的名称、输入后是否回车 |
| `f{id}n`、`f{id}a`、`f{id}k` | 指纹编号 id 的名称、绑定的操作（0–3 = 密码，-1 = 不执行，-2 = 快捷键）、快捷键（修饰键 << 8 \| 键码） |
| `summon` | 设置入口指纹的编号 |
| `wake` | 唤醒等待毫秒数 |
| `fails` | 连续失败次数 |

蓝牙配对信息由 NimBLE 自己保存；命名空间 `ftypeble` 记录每台电脑见过的蓝牙服务列表版本：macOS 会缓存蓝牙服务列表，固件改了服务以后，靠这个版本号判断要不要通知电脑重新读取。

**密码只能写入，固件里没有任何命令能把密码读出来。** 解密只在打字前的一瞬间发生，用完马上清零。

## 8. 固件升级（OTA）

1. 网页读取 `.bin` 文件，检查第一个字节是 `0xE9`（ESP32 固件格式），并找到识别标记 `FTYPFW1:` 后面的版本号。不是本项目的固件就不让导入。
2. `otaBegin`：参数 `size`（字节数）、`sha256`（64 位十六进制）、`chunk`（可选，每段大小，最大 4096）。需要验证指纹。设备回复实际使用的 `chunk`。
3. `otaData`：参数 `off`（这一段的起始位置）、`d`（这一段的 Base64）。必须按顺序发，设备回复 `off` = 已写入的字节数。
   - 蓝牙：每段 1536 字节，发一段等一段，全程约 30 分钟；
   - USB：每段 4096 字节，同时最多两段在路上，约 25 秒。
4. `otaEnd`：设备核对 SHA-256 和识别标记，无误后把新固件设为下次启动的固件，回复后重启。
5. 出错或中途放弃发 `otaAbort`；30 秒没收到数据，设备也会自动放弃。任何时候失败，原来的固件都不受影响。

分区表用的是 PlatformIO 默认的 `default_8MB.csv`（两个 3.2 MB 的程序分区，轮流使用）。

## 9. 常用参数（`src/config.h`）

| 参数 | 默认 | 说明 |
|---|---|---|
| `PRODUCT_NAME` / `DRIVE_LABEL` | Fingertype / FINGERTYPE | 蓝牙名称、配置盘卷标（卷标正好 11 个字符，大写，不足补空格） |
| `MAX_ACCOUNTS` | 4 | 最多存几个密码 |
| `MAX_PASSWORD_LEN` | 64 | 密码最长字符数（目前只支持可打印 ASCII，美式键盘布局） |
| `ENROLL_SAMPLES` | 4 | 录入一枚指纹按几次 |
| `FP_POLL_MS` | 40 | 多久问一次模块有没有手指 |
| `AUTH_SESSION_MS` | 2 分钟 | 验证指纹后多久内可以修改设置 |
| `LOCKOUT_AFTER` / `LOCKOUT_BASE_MS` / `LOCKOUT_MAX_MS` | 5 次 / 30 秒 / 10 分钟 | 连续失败锁定 |
| `DEFAULT_WAKE_DELAY_MS` | 800 | 唤醒屏幕后等多久再输入密码 |
| `SUMMON_HOLD_MS` | 5000 | 设置入口指纹按住多久弹出配置盘 |
| `PAIRING_WINDOW_MS` | 60 秒 | 配对窗口时长 |
| `BLE_RECONNECT_WAIT_MS` | 6000 | 按手指时蓝牙没连上，最多等多久 |
| `FIRMWARE_VERSION` | — | 每次发布改一下，网页升级时会显示 |

## 10. 想自己改的话，可以从这些地方入手

- **换指纹模块**：重写 `src/fp_module.*`，保持 `getImage / genChar / search / regModel / store / remove` 这几个接口不变，其余代码基本不用动。
- **换主控**：需要支持 BLE 和 USB 设备模式（同时当键盘 + 串口 + U 盘）。ESP32-S3 是目前最省事的选择；ESP32-C3 / C6 没有 USB OTG，做不了 USB 键盘和配置盘。
- **加功能**：在 `main.cpp` 的 `dispatch()` 里加命令，网页里用 `run('命令名', {...})` 调用。
- **改网页**：只改 `web/Settings.html`，重新编译固件即可；也可以直接用 Chrome 打开它调试。
- **非美式键盘布局、中文密码**：需要改 `ble_keyboard.cpp` 里的 `asciiToHid()` 和 USB 打字部分。
